# 12. Архитектурные решения и источники

Дата проекта: 28 сентября 2026. Это стартовая спецификация, версия 0.1. Решения ниже приняты для планирования и могут быть пересмотрены через отдельную ADR с причиной и последствиями.

## Реестр решений

| ID | Решение | Причина и цена |
| --- | --- | --- |
| ADR-001 | 2D сетка и вид сверху | Хорошая читаемость тактики, ограниченный бюджет графики; нет 3D-перемещения |
| ADR-002 | Постоянный персонаж + риск добычи экспедиции | Совмещает долгую жизнь MMO и напряжение рогалика; основной режим не имеет полной permadeath |
| ADR-003 | Одновременная симуляция 10 Гц | Группа не ждёт одного игрока; часть классической пошаговости заменена временем действий |
| ADR-004 | Laravel + отдельный PHP CLI цикл | Сохраняет выбранный стек и отделяет задержки HTTP; требует контроля памяти долгоживущих процессов |
| ADR-005 | Модульный монолит | Простой запуск и общие транзакции; дисциплина границ важнее количества сервисов |
| ADR-006 | MySQL — источник истины, Redis — вспомогательное хранилище | Понятные гарантии активов; нагрузку журнала надо измерить |
| ADR-007 | Один владелец зоны с fencing epoch | Два процесса не подтверждают одно состояние; нужны аренда и проверки каждой записи |
| ADR-008 | JSON по HTTPS/WSS | Удобная диагностика и поддержка Pascal; выше трафик, чем у бинарного формата |
| ADR-009 | Pascal/Lazarus и отдельный SDL2 рендер | Соответствие стеку, простой редактор; сетевой адаптер и упаковка требуют spike |
| ADR-010 | Версионированный контент | Повторы и старые забеги не меняются при патче; одновременно хранятся несколько версий |
| ADR-011 | Торговля после вертикального среза | Сначала надёжное владение и награды; рынок не задерживает проверку боя |
| ADR-012 | Docker Compose до доказанной необходимости оркестратора | Низкая сложность эксплуатации; отказоустойчивость узла обеспечивается отдельной работой |

## Что ещё нужно подтвердить

- Конкретные версии Lazarus/FPC, SDL2 bindings и сетевой библиотеки на Linux/Windows.
- Event loop PHP: прототип кандидата Workerman, взаимодействие с Laravel и драйвером БД.
- Как синхронная долговечная запись тактов влияет на p99 при 100 CCU.
- Соотношение ручных комнат и процедурной генерации, бюджет рисунка/анимации.
- Формулы прогресса, ремонта, предметов и сложностей по плейтесту.
- Хостинг, регион запуска, расходы на backup/трафик и политика данных.
- Окончательное публичное название и модель финансирования.

## Проверенные первичные источники для базового стека

- [Laravel 13: release notes и требования PHP](https://laravel.com/framework/docs/13.x/releases). Документация указывает минимум PHP 8.3; PHP 8.4 выбран внутри поддерживаемого диапазона. Это проверка совместимости основных версий, а не доказательство совместимости всех будущих пакетов.
- [Официальные загрузки Lazarus](https://download.lazarus-ide.org/). Конкретная поставка и связанный компилятор фиксируются на S0; номер «самой новой» версии в проекте намеренно не утверждается без сборочного теста.
- [MySQL: Innovation и LTS](https://dev.mysql.com/doc/refman/8.4/en/mysql-releases.html). Выбрана ветка 8.4 LTS как консервативная база проекта; это не утверждение, что она самая новая.

Механики игры, числа баланса, сроки и архитектурные ограничения — собственные проектные предложения. Они не приписываются документации Laravel, Lazarus, MySQL, World of Warcraft или Dungeon Crawl. Упоминание игр задаёт направление дизайна и не подразумевает копирование их ресурсов или реализацию идентичных правил.
