# Первая игровая версия — 0.3.0 «Три огня»

Локальная кооперативная RPG для 1–4 игроков. Это первая игровая поставка, а не завершение всей MMO из первоначального дизайн-проекта.

## Запуск

На этой машине сервер работает через Docker Desktop. Двойной щелчок по `Play.cmd` проверяет сервер и запускает игру. Также можно открыть `dist/windows/GrimHollow.exe` или выполнить `tools/play.ps1` из PowerShell. Для повторного запуска сервера используйте `tools/setup.ps1`: существующая база сохраняется.

Адрес клиента: `http://127.0.0.1:8080`. WebSocket: `ws://127.0.0.1:8082`; внутренний порт контейнера — 8081. Не удаляйте Docker volume `grim-hollow_mysql-data`: в нём аккаунты и прогресс. `docker compose down` сохраняет volume, `down -v` удаляет его.

1. Зарегистрируйтесь или войдите прежним аккаунтом. Создайте героя одного из четырёх классов.
2. Во вкладке «Вещи» наденьте кольцо. Оружие, броня и щит уже выданы.
3. «Поход» → первая область → «Подготовить / присоединиться» → «Начать». Друзья входят по коду до старта.
4. Щёлкните карту или нажмите Esc. Стрелки/WASD — движение; Space — атака; 1–3 — боевые действия и зелье; 4–7 — магия.
5. У золотого выхода X эвакуирует с добычей, E ведёт глубже. Для продвижения кампании победите босса третьего этажа и эвакуируйтесь.

**F1** открывает полный справочник в игре. **T** открывает городские службы после возвращения. **R** помогает соседнему павшему союзнику: начать за 20 секунд, продержаться 3 секунды без урона. На переходах между этажами доступно одно автоматическое воскрешение за поход.

## Содержание

- Кампания из трёх областей: затопленные шахты → монастырь → корни Разлома. В каждой три процедурных этажа. У областей разные палитры, seed, сила врагов, награды и имена боссов; базовые алгоритмы врагов общие.
- Финал фиксируется после возвращения третьего огня. Дальше можно повторять экспедиции, развивать персонажей и пользоваться городом.
- Страж, арканист, следопыт с дальней атакой и хранитель с лечением союзников. До восьми персонажей на аккаунт.
- 20 уровней, характеристики, по два направления талантов на класс, четыре заклинания, 11 определений предметов, четыре слота экипировки.
- Город: кузница, разбор вещей, четыре рецепта, запасы зелий, торговая доска с комиссией 5%, гильдии, друзья, хроника прогресса и экономических операций.
- Общий, групповой и гильдейский чат; жалобы на сообщения и отдельный экран модератора.
- Pascal/Lazarus-клиент с пиксельными персонажами и каменными тайлами, иллюстрацией города, миникартой и классическими панелями в стиле старых Delphi-игр.

Золото и вещи похода сохраняются при эвакуации; поражение оставляет четверть заработанного опыта. Постоянная экипировка не пропадает. Надетая вещь привязывается: её можно продать торговцу или разобрать, но нельзя выставить игрокам. Новые стартовые вещи тоже привязаны.

## Архитектура поставки

`packages/game-core` — детерминированные правила, генерация, каталог и проверка команд. `apps/server/app/Game` — транзакции персонажей, города, походов и воспроизведение журнала. Laravel обслуживает HTTP, Workerman — мир и WebSocket, MySQL хранит состояние и уникальные подтверждения операций.

В клиенте `Main` управляет сеансом; `GameLayout` и `GamePanels` — компоновкой; `GameData` — чтением и подписями данных; `GameRenderer` и `GameArt` — сценой; `TownWindow` — городом; `FieldGuide` — справочником; `GameTransport` — фоновыми HTTP-запросами; `NativeNetwork` — Windows HTTPS/WebSocket. Проект IDE: `apps/client/GrimHollow.lpi`.

Windows использует WinHTTP с системной проверкой сертификатов и полными WebSocket-снимками. Команды идут через HTTP/HTTPS. Linux в этой поставке использует локальный HTTP polling; Linux TLS/WSS ещё не реализован. Сервер умеет обновлять сессии и отзывать связанные соединения. Интерфейс сохраняет одну следующую команду, пока предыдущая ожидает ответа.

## Обслуживание и проверки

```powershell
./tools/test-mysql.ps1
./tools/test-client.ps1
node tests/e2e/smoke.mjs
node tests/e2e/rpg.mjs
node tests/e2e/gameplay.mjs
./tools/backup-verify.ps1 -Verify
```

MySQL-тесты работают в отдельной базе `grim_hollow_test`. Проверка резервной копии импортирует её в отдельную базу с временной меткой. Сетевые тесты создают тестовые аккаунты в работающем локальном сервере.

Администрирование: `/admin`. Обычный аккаунт не получает административных прав через API. Выдать роль оператору можно командой `php artisan game:admin EMAIL` внутри API-контейнера, отозвать — с `--revoke`. `game:status` показывает состояние, `game:verify-replay ID` сверяет журнал нового похода с сохранённым снимком. Старые походы без genesis не воспроизводятся этой командой.

Подготовлен `infra/compose/production.yaml` с PHP-FPM, Nginx и Caddy. Образ PHP-FPM собран, но публичный профиль не развёрнут и целиком не проверен: нет заданного сервера и домена. Он не заменяет локальный профиль автоматически.

## Граница первой версии

Пока нет Linux TLS/WSS, подписанного автообновления, email verification/восстановления пароля, звука, полного набора контента исходного MMO-плана, распределённых world-процессов и измеренного теста 100 сетевых игроков. Город представлен сценой и службами, а не общей зоной с передвижением всех игроков. Нужны дальнейшие прохождения для балансировки кампании. Полные ручные проверки всей кампании и публичный запуск не заявляются.

Актуальные результаты проверок — в [статусе реализации](00-implementation-status.md). Дальнейший MMO-план — в [дорожной карте](11-roadmap.md).
