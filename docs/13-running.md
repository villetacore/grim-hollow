# Сборка, запуск и проверка прототипа

## Windows: сервер

Нужен работающий Docker Desktop с Linux containers. Из корня проекта:

```powershell
.\tools\setup.ps1
```

Скрипт создаёт случайные локальные секреты в `infra/compose/.env`, собирает образ, запускает MySQL, применяет миграции и поднимает API/world. Повторный запуск сохраняет данные. `.env` не публикуется. Для этого проекта используются собственные Docker Compose имя, сеть и volume.

На этой машине подготовлен `dist/windows/GrimHollow.exe`. Запуск:

```powershell
.\tools\play.ps1
```

Если бинарник отсутствует, установите Lazarus/FPC либо укажите локальную распакованную IDE переменной `LAZARUS_HOME`, затем выполните `tools/build-client.ps1`. Исходный проект — `apps/client/GrimHollow.lpi`. Linux-компилятор не создаёт Windows-бинарник автоматически.

## Linux

```sh
sh tools/setup.sh
docker build -f infra/docker/client/Dockerfile -t grim-hollow-client:dev .
```

Для обычного графического запуска удобнее открыть `.lpi` в локальном Lazarus и собрать клиент для своей ОС. Контейнер клиента служит воспроизводимой Linux-сборкой и автоматической GUI-проверкой. Бинарник контейнера требует совместимую Linux x86-64 среду и GTK2; он не является универсальным статическим AppImage.

## Управление игрой

1. Создать аккаунт или войти. Токен и пароль не сохраняются на диск.
2. Создать героя. При входе существующего аккаунта клиент выбирает первого героя.
3. Оставить код группы пустым для новой экспедиции. Второй клиент вводит показанный лидеру код перед стартом.
4. Лидер нажимает «Начать». В текущем прототипе город заменён панелью подготовки.
5. После старта управление автоматически переходит на карту. Синий круг с HP — ваш герой. Двигаться WASD/стрелками; бить соседнего врага Space; 1 — удар с оглушением; 2 — защита; 3 — зелье. Если на карте написано «Подготовка», лидер ещё не начал экспедицию. Нажатие во время сетевого обновления сохраняется и выполняется после ответа сервера.
6. Найти золотую клетку выхода. X — эвакуироваться, E — спуститься дальше, когда оставшиеся участники рядом. На третьем этаже сначала нужно победить босса.
7. После поражения или эвакуации можно подготовить новую экспедицию. Кроны закрепляются только при эвакуации, опыт при поражении — на 25%.

Важные ограничения: клиент работает только с loopback HTTP:8080; LAN/интернет-вход пока не предусмотрен. Отключённый герой остаётся в игре до 120 секунд. Зелья временно выдаются заново каждому забегу. Опыт сохраняется, но ещё не повышает уровень. Гильдий и торговли пока нет.

## Проверки

```powershell
# Интеграционные тесты в отдельной MySQL-базе grim_hollow_test
.\tools\test-mysql.ps1

# Два участника, WebSocket, ограничения доступа и повторы команд
node tests/e2e/smoke.mjs

# Реальное исследование первой карты, бой, эвакуация и сохранение
node tests/e2e/gameplay.mjs

# Собрать и проверить Windows GUI-клиент на локальном сервере
.\tools\test-client.ps1
```

Сетевые тесты создают отдельные тестовые аккаунты в dev-базе; ограничения регистрации остаются активными. Не запускайте много прогонов подряд в одну минуту: 429 является ожидаемой защитой. Gameplay-тест зависит от случайной карты/боевых событий и имеет предел 150 секунд; он дополняет детерминированные unit tests, а не заменяет их.

GUI smoke запускается в контейнере клиента через `xvfb-run` с аргументом `--smoke` и сетью `grim-hollow_default`. Он создаёт собственный аккаунт, входит в экспедицию и сохраняет BMP в `/artifacts`. Этот режим предназначен только для тестов.

Из корня Laravel при локальном PHP 8.4+ можно выполнить `composer install` и `php vendor/bin/phpunit`: без внешних DB-переменных тесты используют SQLite in-memory. Это быстрая дополнительная проверка; гарантии блокировок подтверждаются отдельным MySQL-прогоном.

## Остановка и диагностика

```sh
docker compose --env-file infra/compose/.env -f infra/compose/dev.yaml ps
docker compose --env-file infra/compose/.env -f infra/compose/dev.yaml logs --tail 100 api world
docker compose --env-file infra/compose/.env -f infra/compose/dev.yaml down
```

Обычный `down` сохраняет volume с персонажами. Не добавляйте `--volumes`, если хотите сохранить игру. Перезапуск world читает подтверждённое состояние из MySQL; полная потеря volume без backup не восстанавливается.

PHP и Composer для текущей рабочей машины лежат в `.tools`, инструменты сборки также локальные. Они исключены из репозитория и не заменяют инструкции установки зависимостей на другой машине.
