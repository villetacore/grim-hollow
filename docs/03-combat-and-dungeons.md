# 03. Бой и процедурные экспедиции

## Время и перемещение

Серверный такт — 100 мс. Игроки действуют одновременно; ожидание одного клиента не останавливает мир. Движение — по четырём соседним клеткам, стандартная длительность шага 300 мс. Диагональные перемещения отсутствуют в первой версии; дальность считается манхэттенским расстоянием, луч обзора — отдельным алгоритмом по сетке.

Клиент отправляет намерение, сервер назначает первый допустимый такт исполнения. На персонажа хранится только одно следующее действие: новая команда заменяет ещё не начатое действие, но не отменяет уже начатую атаку без предусмотренного правила отмены. Удержание клавиши обновляет намерение движения. Запас энергии не накапливается за счёт потери связи.

При попытке двух существ занять клетку побеждает фиксированный порядок инициативы, затем стабильный ID существа. Обмен клетками союзников допускается только согласованной парой шагов на одном такте; иначе обе клетки заняты. Инициатива фиксируется в начале столкновения и не зависит от скорости доставки пакета.

## Порядок обработки такта

1. Проверка команд: владелец, состояние, последовательность, лимиты, готовность умения.
2. Завершение перемещений и проверка коллизий.
3. Завершение применений умений; дальность и линия видимости проверяются повторно.
4. Периодические эффекты, поверхности, смерть и возрождение.
5. Обновление поведения AI и постановка следующих действий.
6. Фиксация событий, обновление видимости, рассылка подтверждённой дельты.

Порядок важен для воспроизводимости: если яд убил цель в этой фазе, уже завершившаяся ранее атака остаётся действительной. Урон, смерть и выпадение добычи получают уникальные идентификаторы событий.

## Базовые правила урона

Черновая модель для прототипа:

```text
raw = base_damage + floor(power * skill_coefficient_bp / 10000)
physical = floor(raw * 100 / (100 + max(0, armor)))
elemental = floor(raw * (10000 - clamped_resistance_bp) / 10000)
critical = floor(damage * 15000 / 10000) при успешной проверке критического удара
final = max(0, critical - absorbed_by_shield)
```

Сопротивление ограничено диапазоном −5000…7500 базисных пунктов. Физический и стихийный компоненты считаются раздельно. В одной атаке выполняется одна проверка попадания; базовая вероятность 90%, итог ограничен 50–98%. Критический удар проверяется только после попадания. Умения с гарантированным попаданием явно помечаются в данных. Лечение не критует в первой версии.

Все формулы серверные. Округление вниз после каждого указанного шага. Для повторов фиксируются алгоритм генератора псевдослучайных чисел, его версия и состояние; использование системного `rand()` внутри правил запрещено.

## Эффекты и окружение

| Система | Правило прототипа |
| --- | --- |
| Яд | До 3 зарядов; повтор обновляет длительность; урон раз в 10 тактов |
| Горение | Не складывается, выбирается больший урон; вода снимает |
| Оглушение | Не более 2 с за 10 с для игрока; боссы имеют собственное сопротивление |
| Вода + молния | Распространение на соседние мокрые цели, максимум 3 перехода |
| Масло + огонь | Создаёт горящую поверхность на 5 с |
| Шум | Привлекает врагов в радиусе с поправкой на стены и двери |
| Туман войны | Сервер передаёт только видимые сущности и известную ранее геометрию |

Прямой дружественный огонь выключен. Опасные поверхности, созданные игроком, также не наносят урон союзникам в первой версии; ловушки мира опасны для всех. Это правило можно изменить только отдельным модификатором контракта с явным предупреждением.

## Противники

AI — конечный автомат: покой → подозрение → поиск → преследование → атака → отступление → возвращение. Навигация по A* на небольшой карте, результаты путей кэшируются по ревизии препятствий. Пересчёт распределяется по тактам, чтобы все враги не искали путь одновременно.

Архетипы первого среза: падальщик преследует ближайшую цель, костяной стрелок держит дистанцию, болотный плевун создаёт яд, слепой громила идёт на шум. Босс «Смотритель шлюза» закрывает проходы, затапливает сектора и объявляет удар за 1,2 секунды. Сигнал виден формой и анимацией, а не одним цветом.

Для группы здоровье врага: `base_hp × (1 + 0,65 × (players − 1))`. Это исходная гипотеза баланса. Число игроков фиксируется при входе; отключение не ослабляет босса. Урон растёт только с выбранной сложностью, количество целей и угроз — с числом участников. Все коэффициенты выносятся в контент.

## Генерация подземелья

Вход: серверный seed, версия генератора, версия контента, биом, этаж, сложность и состав группы. Выход: сетка, старт, выход, граф комнат, двери, встречи, контейнеры и цели контракта.

Алгоритм:

1. Сгенерировать граф из 8–14 комнат: обязательный путь и 2–4 боковые ветви.
2. Разместить комнаты шаблонов в сетке 64×64 и соединить коридорами.
3. Выбрать вход, выход и безопасную стартовую область; исключить врагов в радиусе 6 клеток от входа.
4. Расставить цели, ключи и запертые двери; ключ всегда доступен до соответствующей двери.
5. Распределить встречи по бюджету угрозы, затем ловушки, добычу и декорации.
6. Проверить связность, достижимость целей, отсутствие наложений, бюджет опасности и возможность прохода всей группы.
7. При ошибке повторить до 10 раз; затем применить проверенный резервный шаблон того же биома и записать диагностику.

Скрытый seed и будущие этажи не передаются клиенту. Одинаковый seed воспроизводит карту только вместе с версиями генератора и контента. Состояние случайности для боя отделено от случайности карты и выпадения предметов.

## Выборы внутри забега

После ключевой встречи игрок выбирает одну из трёх личных временных реликвий. Групповая развилка выбирается большинством за 20 секунд; ничья решается лидером, отсутствие выбора — безопасной веткой. Следующий этаж запускается после готовности всех живых участников либо по таймеру 30 секунд с явным уведомлением. Перед переходом разрешена личная эвакуация; участник завершает свой забег и больше не возвращается в него.

Каждый этаж увеличивает тревогу: дольше находишься — чаще появляются патрули. Есть жёсткий срок жизни экспедиции 60 минут; за 5 минут открывается аварийный выход, по истечении срока оставшиеся участники считаются проигравшими. Таймер останавливается при административной паузе и аварийном восстановлении.
