# Grim Hollow — Три огня

Кооперативная 2D RPG-рогалик на PHP/Laravel и Object Pascal/Lazarus. Классический стек, процедурные подземелья и интерфейс в духе Delphi-игр. Собственный мир и графика; ресурсы World of Warcraft и Dungeon Crawl не используются.

**Версия 0.3.1:** локальная игровая поставка для 1–4 игроков. Есть кампания с финалом, четыре класса, развитие, городские службы и экономика. Это не завершение всех этапов исходного MMO-проекта. [Реализовано и проверено](docs/00-implementation-status.md).

## Игроку

Скачайте Windows x64-клиент в Releases, распакуйте и запустите `GrimHollow.exe`. Адрес HTTPS-сервера предоставляет организатор игры; клиентский архив не содержит сервер. Linux x64/GTK2-клиент этой версии пока работает только с локальным HTTP.

**F1** — справочник, **T** — город, **Esc** — фокус на карте. WASD/стрелки — движение, Space — атака, 1–3 — боевые действия, 4–7 — магия. [Полное руководство игрока](docs/17-player-guide.md).

## Локальный запуск из исходников

Нужен Docker Desktop с Linux containers (Windows) либо Docker Engine + Compose v2 (Linux). Для сборки Windows-клиента установите Lazarus/FPC. PHP/Composer на хосте для Docker-сервера не требуются.

```powershell
./tools/setup.ps1
./tools/build-client.ps1
./tools/play.ps1
```

После первой сборки двойной щелчок по `Play.cmd` запускает локальную игру. Linux-сервер: `sh tools/setup.sh`; клиент собирается проектом `apps/client/GrimHollow.lpi` или Dockerfile в `infra/docker/client`.

API: `http://127.0.0.1:8080`; WebSocket: `ws://127.0.0.1:8082` (внутри контейнера 8081). Порты dev публикуются только на loopback. Настройки генерируются в непубликуемом `infra/compose/.env`. Сохранения находятся в Docker volume MySQL; не используйте `down -v`, если хотите сохранить аккаунты.

## Что есть в игре

- Три области по три процедурных этажа, боссы и последовательное возвращение трёх огней.
- Страж, Арканист, Следопыт, Хранитель; до восьми героев аккаунта; группы до четырёх игроков.
- Инвентарь, экипировка, магия, 20 уровней, характеристики, таланты, поднятие союзника.
- Кузница, разбор вещей, запасы, торговая доска, друзья, гильдии, три канала чата и модерация.
- Пиксельные тайлы и персонажи, миникарта, городская сцена, классические панели и встроенный справочник.

## Стек и структура

| Каталог | Содержание |
| --- | --- |
| apps/server | Laravel 13 / PHP 8.4, HTTP API, Workerman world |
| apps/client | Object Pascal / Lazarus / LCL Canvas, Windows и Linux |
| packages/game-core | Детерминированные правила, генерация, каталог, команды |
| packages/protocol-pascal | Pascal-часть протокола |
| infra | Docker, MySQL 8.4, Nginx, Caddy, Compose |
| tests | Сетевые сценарии, прохождение бота, упаковка |
| tools | Запуск, сборка, тесты, backup, архивы релиза |
| docs | Руководства, архитектура, дизайн и фактический статус |
| .github/workflows | CI-проверки, сборка клиентов и публикация релизов |

Сервер хранит подтверждённое состояние и экономические операции в MySQL. Windows использует WinHTTP HTTPS/WebSocket; Linux — локальный HTTP polling. SDL2 и Redis из целевого проекта в текущей реализации не используются.

## Проверки и выпуск

```powershell
./tools/test-mysql.ps1
./tools/test-client.ps1
node tests/e2e/smoke.mjs
python tools/release.py check
python -m unittest discover -s tests/packaging
```

При push/PR GitHub Actions проверяет сервер, собирает Windows/Linux-клиенты и выполняет Linux GUI/сетевые сценарии. Push тега `v0.3.0`, совпадающего с VERSION, запускает полный pipeline, затем публикует GitHub Release и образ `ghcr.io/owner/repository:0.3.0`. Секреты сервера и SSH-доступ CI не нужны. Автоматического развёртывания нет.

**[Публикация репозитория, CI/CD, релизы и самостоятельный сервер](docs/16-distribution.md)** — пошаговая инструкция. Чистый архив исходников создаёт `python tools/release.py source`; локальные секреты и данные исключены.
